# Social share cards (og:image)

A 1200&times;630 screenshot of the hero, one per locale, wired into every page's
metadata. Without one, a shared link renders as a bare text row in WhatsApp.

| | |
|---|---|
| **Helper** | `lib/ogImage.ts` (from `templates/site-chrome/ogImage.ts`) |
| **Generator** | `scripts/og-shot.mjs` |
| **Output** | `public/og-{locale}.png` |
| **Owner** | Kimmy (metadata), generated at Step 8 |
| **Wizard check** | `og-image-per-locale` — blocking |
| **Verified** | 17 Aug 2026 |

Malaysian traffic arrives through WhatsApp shares more than any other channel, so this
is not a nice-to-have — it is the first impression for a large share of visitors.

---

## The two traps that make this fail silently

**1 &middot; Next replaces `openGraph` wholesale.** A page that defines its own
`openGraph` object does **not** inherit `images` from the layout — the whole object is
replaced. This is exactly how a site ships with a working card on the homepage and no
card at all on location and blog pages, which is where most shared links point.

Every page that defines `openGraph` must spread `ogImages(locale)` in itself.

**2 &middot; The card is a screenshot, so it goes stale invisibly.** Change the hero
copy, the hero image, or the palette and the site still looks correct — only the shared
link is wrong, and nothing in the build will tell you. Regenerate after any hero change.

## The helper

```ts
import { siteConfig } from '@/config/site';

/**
 * Social share card — a 1200x630 screenshot of the hero section, one per locale
 * (`public/og-{locale}.png`), generated by `scripts/og-shot.mjs`.
 *
 * Regenerate after ANY hero copy / image / palette change. The card is a
 * screenshot, so a stale one is invisible: the site looks right and only the
 * shared link is wrong.
 *
 * Relative URLs resolve against the `metadataBase` set in
 * app/[locale]/layout.tsx — set it, or the card URL comes out relative and most
 * scrapers reject it.
 *
 * Next.js replaces a parent's `openGraph` object WHOLESALE when a page defines
 * its own, so every page that sets `openGraph` must spread this in explicitly.
 * Inheriting it from the layout does NOT work — that is exactly how sites ship
 * with a share card on the homepage and none on location or blog pages.
 */
export function ogImage(locale: string) {
  const known = (siteConfig.locales as readonly string[]).includes(locale);
  return {
    url: `/og-${known ? locale : siteConfig.defaultLocale}.png`,
    width: 1200,
    height: 630,
    alt: siteConfig.tagline,
  };
}

/** Ready-to-spread `images` array for `openGraph` / `twitter`. */
export function ogImages(locale: string) {
  return [ogImage(locale)];
}
```

`metadataBase` must be set in `app/[locale]/layout.tsx` or the card URL comes out
relative and most scrapers reject it outright.

```ts

  return {
    metadataBase: new URL(siteConfig.url),
    title: t('title'),
    description: t('description'),
    alternates: {
      canonical: `${localeHref(locale)}`,
      languages,
    },
    openGraph: {
      type: 'website',
      url: `${localeHref(locale)}`,
      siteName: siteConfig.brandName,
      title: t('title'),
      description: t('description'),
      locale: OG_LOCALE[locale] || 'ms_MY',
      alternateLocale: routing.locales.filter((l) => l !== locale).map((l) => OG_LOCALE[l]),
      images: ogImages(locale),
    },
    twitter: { card: 'summary_large_image', images: ogImages(locale) },
  };
}
```

## A page with its own `openGraph`

```tsx
// A page that defines its OWN openGraph must spread the images in explicitly —
// Next replaces the parent object wholesale, it does not merge.
export async function generateMetadata({ params }) {
  const { locale } = await params;
  return {
    title,
    description,
    openGraph: {
      title, description,
      url: `${localeHref(locale)}${path}`,
      type: 'website',
      images: ogImages(locale),          // <- without this the card vanishes
    },
    twitter: { card: 'summary_large_image', images: ogImages(locale) },
  };
}
```

## The generator — three per-project edits

`LOCALES` must match `i18n/routing.ts` (with `localePrefix: 'as-needed'` the default
locale has **no** prefix). `PORT` must match the `start` script. `HIDE` takes any
hero-foot element a 630 crop would slice mid-text — a sliced stat row reads as a
rendering bug.

```js
// ── Configure per project ────────────────────────────────────────────────
const LOCALES = [
  ['ms', ''],      // default locale — no prefix under localePrefix:'as-needed'
  ['en', '/en'],
  ['zh', '/zh'],
];
const PORT = 3000;
const HIDE = [
  '.fomo-bar', '.site-header', 'header',   // canonical chrome
  '.hero-stats', '.ops-ticker',            // hero-foot elements a crop would slice
];
// ─────────────────────────────────────────────────────────────────────────

const W = 1200;
const H = 630;
const ORIGIN = process.env.OG_ORIGIN ?? `http://localhost:${PORT}`;

const browser = await puppeteer.launch({ headless: true, args: ['--no-sandbox'] });
```

## Running it

```bash
# one shell — the card is a screenshot of the real site
npm run build && npm run start

# another shell
node scripts/og-shot.mjs
# -> public/og-ms.png, public/og-en.png, public/og-zh.png  (1200x630 each)

# `next start` snapshots public/ at boot, so restart it to serve the new files
lsof -ti:3000 | xargs kill -9     # pkill -f "next start" does NOT match —
                                   # the process is named next-server
npm run start
```

## Why the generator is built the way it is

Each of these cost real debugging:

- **Two passes** — hide the chrome, measure the hero, *then* fit it. A blind
  1200&times;630 clip lets whatever sits below the hero leak into the bottom of the card.
- **Padding injected as a stylesheet with `!important`** — an inline style loses to the
  earlier `padding-top: 0 !important`.
- **Both short and tall heroes handled** — pad symmetrically when short, clip from the
  **top** when tall. Top-anchored because the logo, H1, H2 and CTA all sit in the upper
  two-thirds; a centred crop decapitates the logo.

## What breaks it

**A card on the homepage only** · *silent*
The wholesale-replacement trap. The homepage inherits from the layout and works; the
location and blog pages define their own `openGraph` and lose the image. Shared links
from those pages — the majority — render bare.

**No `metadataBase`** · *silent*
The URL resolves relative and scrapers reject it. **24 of 31 projects set it**, so
seven currently don't.

**A stale card** · *silent*
Hero changed, card didn't. The site looks right; only the share preview is wrong.

**No cards at all** · *blocking*
Three projects have none: `boom-lift-rental`, `katering-auntyrokiah`,
`waterproofing-my`. 28 of 31 have them.

**Writing PNGs while `next start` runs** · *visible, confusing*
It snapshots `public/` at boot, so new files 404 until you restart. And
`pkill -f "next start"` doesn't match — the process is named `next-server`. Use
`lsof -ti:<PORT> | xargs kill -9`.
