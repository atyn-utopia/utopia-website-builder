```
    ├── /zh/pakej-katering/<location>                    ← 160 ZH location pages
    └── /zh/blog + /zh/blog/<slug>
```

Keyword-to-page assignment (anti-cannibalisation):

| Page | Primary KW (BM) | Primary KW (EN) | Primary KW (ZH) |
|------|-----------------|-----------------|-----------------|
| `/[locale]` (homepage) | pakej katering Malaysia / katering kenduri Malaysia | wedding catering Malaysia / malay catering services | 马来婚宴餐饮 |

| `/[locale]/blog/<slug>` | one informational long-tail per post | one informational long-tail per post | one informational long-tail per post |

Homepage never claims a city-specific primary keyword (avoids stealing rank from location pages). City pages never claim "Malaysia"-level head terms — they own city + use-case combos only.

## 8. Hreflang strategy

Every page must emit exactly **3 hreflang `<link>` tags + 1 `x-default`**. Implementation runs via Next.js `generateMetadata({ alternates: { languages: { ... }, canonical: ... } })`.

Templates (base URL = `https://auntyrokiah-katering.utopiaai.my`):

```html
<!-- on every page -->
<link rel="alternate" hreflang="ms-MY" href="https://auntyrokiah-katering.utopiaai.my/ms/<path>" />
<link rel="alternate" hreflang="en-MY" href="https://auntyrokiah-katering.utopiaai.my/en/<path>" />
<link rel="alternate" hreflang="zh-Hans-MY" href="https://auntyrokiah-katering.utopiaai.my/zh/<path>" />
<link rel="alternate" hreflang="x-default" href="https://auntyrokiah-katering.utopiaai.my/ms/<path>" />
<link rel="canonical" href="https://auntyrokiah-katering.utopiaai.my/<currentLocale>/<path>" />
```

Rules:
- `x-default` → BM (`/ms/...`), matching the default locale.
- Locale value for ZH is `zh-Hans-MY` (Simplified for Malaysia). `zh-MY` is acceptable as a fallback but `zh-Hans-MY` is more precise.
- Every URL emits the **same path** in all 3 alternates — locale prefix is the only thing that changes. The 160 location slugs are identical across locales (no localised slugs).
- `redirect-whatsapp-1` does **not** emit hreflang (it carries `noindex,nofollow`).
- `sitemap.xml` uses `<xhtml:link rel="alternate" hreflang="...">` blocks per URL (3 alternates + x-default each).

## 11. Anti-duplicate-content rules for location pages

CLAUDE.md mandates "Location pages must have unique copy." With 160 × 3 = 480 pages, the risk of near-duplicate is real. Every location page MUST differ in these blocks (Nana enforces during copy generation):

1. **Unique intro paragraph (H3 + body, 80–120 words)** — must reference the city by name at least twice and the state once. Use one of: a local landmark, a known kenduri-hall area, a road / mukim, a venue category common to that city (e.g. Putrajaya → "majlis di Dewan Komuniti Presint", Cyberjaya → "majlis korporat di sekitar MaGIC", Seremban → "majlis di Lake Gardens"). Never recycle the landmark across two cities.
2. **Location-specific FAQ #1 (mandatory question)** — must be phrased "Berapa harga pakej katering kenduri di `<City>`?" with an answer that mentions the city + state + at least one nearby city from `nearbyMap`. This combo cannot exist on any other page.
3. **Location-specific FAQ #2 (mandatory question)** — must be phrased "Adakah AuntyRokiah Katering hantar ke `<City>`?" with an answer that names the 4 `nearbyMap` cities. The four-city set is unique per page (by construction).
4. **Location-specific testimonial line** — Nana writes one quoted testimonial that opens with "<First name>, <City>" (e.g. "Aida, Shah Alam"). Each city gets a different reviewer name; the testimonial body mentions a different food item or pakej than its neighbours where feasible.
5. **Nearby Locations block** — 4 distinct anchors per page (already unique by `nearbyMap`).
6. **Unique meta title and description** — generated from the templates in Section 4.2 with the `<City>` token. Confirm no two pages produce identical strings (impossible if the city name is unique, which it is — every slug maps to one display name).
7. **Hero H1** — always includes the `<City>` display name. **Never abbreviate** to keep the keyword intact.

Lint at the end of Nana's pass (operator runs this manually before Gate 1):
- diff every two intro paragraphs across the 160 — Levenshtein distance must exceed 30% of the shorter string (rough proxy: at least 1 sentence is different verbatim);
- assert every page emits exactly 1 `<h1>` and 1 `<h2>`;
- assert no `<p>` lives outside a heading-led section;
- assert every section heading is preceded by `.eyebrow`.
